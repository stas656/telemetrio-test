## How it is built

Static pages generated by `build.py` (Python 3, standard library only): `lib/page.py` renders the main page, `lib/alt_page.py` the alternative. The existing site is static HTML, so no framework migration was done (brief §17).

| Concern (brief §17) | File |
|---|---|
| Landing page copy | `content/en/copy.json` |
| Prompt examples | `content/en/prompts.json` |
| Demonstration data | `content/en/demo.json` |
| Connection URLs and instructions | `content/en/connections.json` |
| Access terms | `content/en/access.json` |
| Feature availability flags | `config/features.json` |
| URLs, analytics, headline experiment | `config/site.json` |
| Alternative page copy | `content/en/copy-alt.json` |
| Alternative page prompt builder options | `content/en/builder.json` |
| Alternative page refinement walkthrough | `content/en/refine.json` |
| Styles / behaviour | `src/mcp.css`, `src/mcp.js` (shared); `src/alt.css`, `src/alt.js` (alternative); design tokens in `../assets/tokens.css` |

Build:

```
python3 build.py                     # preview of both pages: highlights missing values, adds noindex
python3 build.py --page alt          # build one page (main | alt)
python3 build.py --mode production   # refuses to build until every launch value below is filled
```

Localization: copy `content/en/` to `content/<lang>/`, translate, run `python3 build.py --lang <lang>`.

## Alternative page (B) — concept

Same product claims, connection values, access terms and FAQ as A (shared files), different story:

1. **Prompt builder hero** — the visitor composes their first search from dropdowns (category, country, purpose, format). The page shows the exact prompt, a copy button and an illustrative preview of the result format. It never runs a search. "Connect to …" links under the builder carry the composed prompt into that assistant's setup card.
2. **Refinement walkthrough** — four conversation steps (add a country, narrow a category, ask for a grouped table) with the "current criteria" updating; added criteria are marked green, removed ones struck through.
3. **Prompt anatomy** — one prompt with its category, geography, purpose and format highlighted.
4. **Audiences** — marketers and advertisers, agencies, channel owners, analysts, each with a starter prompt.
5. **Scope** — what the MCP does and doesn't do (no ad buying, geography ≠ subscriber location, database coverage only, no background monitoring).
6. **Connection + access**, **FAQ**, dark **final CTA**.

Validation (2026-10-07): builder updates prompt, preview (table and list) and analytics; composed prompt carries into setup cards; walkthrough works by click, "Next step" and arrow keys; no horizontal overflow at 360 px or 1440 px; CTAs equal and above the fold on mobile; no console errors. Every event carries `page_variant` (`main` / `alt`) so A and B can be compared; the builder adds `mcp_builder_change` with fixed option ids only (no freeform text).

B's canonical URL points to the main MCP URL, so search engines treat it as a test variant of the same page.

Extra launch items for B: confirm builder countries and categories exist in the catalog (`builder.json → verified`) and that refinement / table output work in both assistants (`refine.json → verified`).

## Information needed before publication

**Claude** (`content/en/connections.json → claude`)
- Availability status (available / beta / unavailable)
- Connection URL — where "Connect to Claude" goes (direct install or connector page)
- Setup steps (verified) and, if manual, the MCP server address
- Setup documentation URL
- Authentication method
- Claude account / plan requirements
- Known restrictions (or "None known")
- Disconnect steps

**ChatGPT** (`content/en/connections.json → chatgpt`) — same list as Claude. Do not assume the flows are identical.

**Access terms** (`content/en/access.json`)
- Required Telemetrio plan
- Usage limits
- Trial availability (or "No trial")
- One-line access summary for the final CTA
- FAQ answer for "How much does it cost?"

**FAQ** (`content/en/copy.json → faq`)
- "Do I need coding skills?" — write after both connection flows are tested
- "What does a channel's geography mean?" — confirm against the geographic data definition, then remove the `verify` key

**Site** (`config/site.json`)
- Production URL (canonical), e.g. `https://telemetr.io/mcp`
- Privacy policy and Terms of use URLs
- Optional: social sharing image (1200×630)

**Product verification**
- Conversational refinement and table output work in both assistants
- Demo countries (Ukraine, Poland, Germany) and categories (Business, Marketing, Technology, Startups, Education, Careers) exist in the catalog — rename to the real taxonomy in `demo.json` and `prompts.json`
- Optional: replace mock rows with a verified example and its retrieval date (`demo.json → verified, retrievedAt`)

**Analytics**
- Destination: events are pushed to `window.dataLayer` (connect GTM or your analytics tool)
- Connection status endpoint (`config/site.json → connectionStatusEndpoint`). Proposed response:
  `{ "claude": { "connected": true, "firstSearch": false, "error": null }, "chatgpt": { ... } }`
  Without it, outbound clicks are reported only as `mcp_connect_click`, never as installations.

## Decisions to review

- **Button hover colour:** the design system's hover blue (#3B8FE3) gives 3.4:1 contrast with white text. The page uses Celtic Blue 600 (#0059B2) on hover to meet the 4.5:1 requirement.
- **Category labels** use only the design-system label colours that pass 4.5:1 (Cornflower and Medium slate).
- **Gilroy ExtraBold** is not freely hosted; headings fall back to Inter 800 until a licensed web font file is added.
- **No sticky mobile CTA:** the hero buttons are visible on load and repeated in the menu and final section.
- **Telemetrio database size** is not shown: no verified figure with MCP-specific context was provided.
- **No testimonials or customer logos:** none verified for MCP.
